# 02 — Organisation: files, objects, and who owns them

The user's first sketch had three kinds:
- **canonical:** shipped and pushed;
- **state:** logs, current configurations, the user's own tools;
- **workstation:** the venv, the stack, the built framework.

It points at the right problem, but one axis can't hold it. A run's provenance is state, yet must
never be deleted. A compiled app is workstation, yet is rebuilt from canonical sources. A user's own
tool is state, yet should be authored and versioned like canonical code. This page proposes two
axes instead, maps today's layout onto them, and lists where the boundaries blur.

---

## 1. Two axes: owner × lifecycle

**Owner** says whose it is and where it may travel:

| Owner | Is | Travels by |
|---|---|---|
| **framework** | Heimdall itself: the same on every machine | `git` (Heimdall) |
| **machine** | built or chosen for this computer: compiled for its OS, CPU, compilers and system libraries | nothing; rebuilt per machine |
| **study** | one piece of physics: a work dir | `git` (the work dir), plus its recorded results |

**Lifecycle** says how it comes to exist and what may delete it:

| Lifecycle | Is | Rule |
|---|---|---|
| **authored** | written by a person (or an agent for them), reviewed | in git; never generated over |
| **derived** | rebuilt from authored files plus the machine: installs, builds, caches, generated files | safe to delete; `clean` may remove it; never edited by hand |
| **recorded** | a fact about what happened: provenance, identities, completion markers, results | precious: never deleted automatically; backed up with the study |
| **ephemeral** | logs, FIFOs, temp files, progress | pruned freely |

Every file belongs to exactly one cell, and each cell has one home:

| | authored | derived | recorded | ephemeral |
|---|---|---|---|---|
| **framework** | runner, schemas, tool folders, templates, recipes, docs, tests | generated docs blocks and the JSON schema (tracked, regenerated by `make`) | — | — |
| **machine** | `machine.toml` (machine settings, recipe overrides, cluster defaults), the user's toolkits and patches | downloads, sources, build trees, `stack/`, `venv/`, compiled apps, `flags.mk` | what the stack is: versions, stamps with digests, the system libraries it links | build logs |
| **study** | configs, cards, modules, the study's own tools, deck sources, datasets (or their manifest) | `build/` (modules, plugins), caches | records (provenance, identity, completion, `points.json`), results, drawn decks | point logs, FIFOs, temp |

The configuration layers follow the owners: framework defaults → machine (`machine.toml`) → study
(the run TOML) → one invocation (`--set`). A setting lives in exactly one layer's file. Today it can
sit in several places (a `[cluster]` account in the work dir's tracked `hep.toml`, `setup_extra` in
the tracked `recipes/settings.toml`).

## 2. Today's layout on the grid

### Heimdall (the checkout)

| Path | Cell | Problem |
|---|---|---|
| `framework/`, `src/`, `recipes/*.toml`, `docs/`, `tests/` | framework · authored | — |
| `src/Apps/Paint/base.toml` | framework · authored, but read at run time as **the** house style (`plot.py:166-168`) | changing the style means editing Heimdall (U25) |
| `recipes/settings.toml` `setup_extra`, `recipes/toolkits.d/`, `recipes/patches/` | machine/user · authored, in a tracked tree | editing makes Heimdall dirty: `hep setup` writes `expects = ""`, and every provenance records a dirty Heimdall (U24, U26) |
| `stack/`, `stacks/`, `stash/`, `forge/`, `env/venv/`, `framework/Apps/`, `env/machine.sh` | machine · derived, **inside the checkout** (ignored) | `git clean -x` destroys the stack; editors must be told to skip them; the venv's `heimdall.pth` holds an absolute path (U19, U29) |
| `stack/.stamps/cxx_std` | machine · *configuration*, stored as a stamp, read by `framework/rules.mk:27` | in the folder the docs say to delete stamps from |
| `forge/` | machine · derived **and** ephemeral **and** test scratch: build trees, logs, `make/` flags, C++ test binaries, `scratch/` (a copied work dir, `output/`, `results/`, `pytest/`) | "may be emptied by hand" wipes all of it at once (U20) |
| `bots/` | agent working state, **tracked** | while the reusable `.setup/check_stack.sh` is **ignored** (U33) |

### A work dir

| Path | Cell | Problem |
|---|---|---|
| `configs/`, `modules/` | study · authored, tracked | — |
| `datasets/` | study · authored (reference data), **ignored** | a clone can't run any config with `data=` (U23) |
| `hep.toml` | study · authored, plus a **machine** part (`[cluster]` account and partition) and a frozen `expects` | machine settings travel with the study (U24) |
| `README.md`, `CLAUDE.md`, `Makefile`, `.vscode/` | framework text copied once by `hep setup`, never refreshed (`setup.py:75-80`) | stale after Heimdall changes (U28) |
| `build/` | study · derived | not per stack: switching `HEP_STACK` rebuilds in place (U27) |
| `output/<P>/<run>/<cfg>/<point>/` | **recorded** (`provenance.json`, `identity.json`, `.complete`) **with** ephemeral (`logs/`), derived (`cards/`, `config/`) and FIFOs | deleting "technical files" deletes the skip markers: everything reruns (U21); the template README says provenance is in `results/` (`templates/work/README.md:11`) |
| `output/<P>/.cache/`, `.reproduce/`, `output/plots/` | derived | `output/plots/` (from `hep overlay`) is undocumented |
| `output/…/cluster/<stamp>/` | recorded (job ids, scripts) | `hep clean`'s keep-set is `{"plots", "pre", "post"}` (`house.py:193`), so submission records are listed as orphans; reserved names share the namespace of points and configurations (U30) |
| `results/` | recorded | — |
| `reports/<deck>/` | **authored** `deck.md` and `deck.toml` **with** derived `panels/`, `figures/`, `build/`, `deck.pdf`, all **ignored** | the user's deck text is never in git (U22) |
| `points.json`, `provenance.json` | recorded, with **absolute paths** | moving a work dir breaks the links (U29) |

### Isolated stacks are half wired (U27)

`apps_dir()` and `forge_dir()` follow `HEP_STACK` (`paths.py:188-203`), but much else doesn't:
- **The tool folders hardcode `{hep}/framework/Apps`** (`pythia/tool.toml:4,44`; `yd2rt/tool.toml:5`;
  `plotmerge/tool.toml:12`; `herwig/tool.toml:33,48`), and `placeholders()` has no `{apps}`
  (`paths.py:206-212`). So `hep run` under an isolated stack runs the default stack's apps.
- **A work dir's `build/` is not per stack.**
- **The shell helpers ignore it:** `hep_stash`, `hep_forge` and `hep_stack` (`env/hep_env.sh:146-148`).

### One package registry, six lists (U34)

The set of packages is written in six places, which drift:
- `recipes/packages.toml`;
- `env/stack.toml` (by design: "keeps its own list");
- `_HEP_PACKAGES` in `env/hep_env.sh:21-22`;
- the 13 rows of `hep_status`;
- `recipes/README.md`;
- `docs/02_User_Guide.md`.

`_HEP_PACKAGES` lists `xrootd`, which is not a package, and lacks every isolated-stack package
(podio, edm4hep, gaudi, …), so those never reach `PATH`. The Mac's `hdf5` had to be added by hand.

## 3. The proposed layout

Decided by the user: machine-built things leave the checkout for a **machine root** of their own.
Downloads, sources and builds go in `forge/`; `stack/` holds finished installs only.

```
~/Github/Heimdall/                 framework · authored — the checkout, nothing else
  framework/  src/  recipes/  docs/  tests/  setup.sh  Makefile

$HEP_MACHINE  (default ~/Heimdall-machine; set once in the user's shell, or found next to the checkout)
  machine.toml                     machine · authored: setup lines, recipe overrides (merged), cluster
                                   defaults, extra toolkits, the platform's name
  toolkits/  patches/  tools/      machine · authored: the user's own (tools: see 04)
  forge/
    downloads/                     archives (verified, with sha256)
    src/<pkg>/                     unpacked sources
    build/<pkg>/                   build trees (autotools out of source where possible)
    logs/<pkg>/<attempt>.log       kept per attempt
  stack/                           installs only, plus .stamps/ (digests) and stack.toml (what was built, against which system libs)
  venv/
  apps/                            Heimdall's compiled apps (App_*.exe, Paint.exe, Herwig's repository)
  stacks/<kit>/{stack,venv,apps}   an isolated toolkit, the same shape

<work dir>/
  hep.toml                         study · authored: [work] only (machine parts go to machine.toml)
  configs/  modules/  tools/       study · authored (tools/: the study's own tool folders, see 04)
  decks/<deck>/{deck.md,deck.toml} study · authored, tracked
  datasets/  or datasets.toml      study · authored: small files tracked, large ones by manifest (URL + sha256)
  records/<P>/<run>/<cfg>/<point>/ study · recorded: provenance, identity, .complete, points.json (relative paths)
  results/                         study · recorded: products and pages
  reports/<deck>/                  study · derived: a deck's built outputs
  build/<stack>/                   study · derived: per stack
  .cache/                          study · derived
  logs/                            study · ephemeral: point logs, FIFOs, temp
```

**What this buys:**
- **`git clean -x` is safe** in Heimdall and in a work dir. Nothing in a checkout is precious unless
  it is authored, and authored files are tracked.
- **Several checkouts share one machine root** (a dev branch and a release) without rebuilding the
  stack. Several machine roots (two compilers) serve one checkout through `HEP_MACHINE`.
- **`clean` works by lifecycle:**
  - `hep clean` removes derived and ephemeral things;
  - `hep clean --records` (explicit, with confirmation) removes records;
  - `rm -rf forge/` in the machine root loses no install.
- **Backups follow the grid:** a study's git plus `records/` and `results/`, and the machine's
  `machine.toml`. Everything else is rebuilt.
- **Moving things is safe.** Records store paths relative to their roots; the venv's `.pth` and
  `stacks/<kit>/setup.sh` point at `$HEP_MACHINE`, which is resolved at load time.

Migration: `hep setup --machine <root>` moves an existing install (or links it, as the lab PC's
`stack` → `~/HEP/install` link does today). `hep migrate --layout` renames `output/` into `records/`
and `logs/` in a work dir (phases 3.1, 5.1).

## 4. Naming collisions — U31 (15), U45 (12)

Names a user must keep apart today, and what the proposed layout and schema v3 do:

| Word | Means today | Proposed |
|---|---|---|
| stack / stacks / stash / `env/stack.toml` / `HEP_STACK` | installs; isolated stacks; downloads; a library registry; a toolkit's name | `stack/`; `stacks/<kit>/`; `forge/downloads/`; `stack/stack.toml` (generated); `HEP_KIT` |
| build | a work dir's `build/`; `reports/<deck>/build/`; `forge/`; `framework/Apps/`; `hep build` | `build/<stack>/`; `reports/<deck>/` (no inner build); `forge/build/`; `apps/`; `hep build` |
| output / results / reports | logs, records and caches; products; decks | `logs/`, `records/`, `.cache/`; `results/`; `reports/` (built decks only) |
| Apps | `src/Apps/Paint` (sources and a runtime data file); `framework/Apps` (binaries); `stacks/<t>/Apps` | `src/Apps` (sources); `apps/` in the machine root; the style data in `framework/style/` |
| setup | `setup.sh`; `hep setup`; `.setup/`; `setup_extra`; `[cluster] setup`; `stacks/<t>/setup.sh` | `setup.sh` (load); `hep new` (make a work dir); `machine.toml [shell]` |
| config | 9 meanings (03 §4) | see [03 §4](03_Configuration.md#4-names-that-mean-several-things--u45-12) |
| stamps | `.stamps/`, `.prepared`, `.complete`, `cluster/<stamp>/` (a time), `*.sha256` | `.stamps/` (build), `.complete` (records), `cluster/<time>/` |

## 5. Doc drift — U32 (20)

- **`docs/framework/01_Target.md` §2** shows the pre-split layout:
  - the build files at the root (they are in `recipes/`);
  - `docs/stack/`;
  - `stack/setup_extra.sh` (it is `env/machine.sh`);
  - no `stacks/` and no `toolkits.d/`;
  - a Heimdall `.vscode/` that doesn't exist.
- **"Any other key is refused"** for `hep.toml` (`06_Internals.md:40`, `01_Target.md:199`); but
  `[cluster]` is accepted (`paths.py:75`).
- **`06_Internals.md` §14's layout map** omits `.cache/checks/`, `.reproduce/` and `output/plots/`.
- **The template README** puts provenance in `results/`.
