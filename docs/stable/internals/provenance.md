# Provenance and manifests

- **`records/…/<point>/provenance.json`:** the point's values; identity, seed, threads, events; per tool its binary's path, sha256 and version, argv, card and sha256, config, and result (exit, seconds, warnings and errors each once with count and first line, its `summary` and last σ); the `--set`s; host, platform, user, times; `git = {heimdall, work}` revisions and dirty flags; `heimdall`, `work`, `stack`. `heimdall reproduce` runs a point again from it, warning when a revision moved or was dirty.
- **`records/…/<point>/attempts.jsonl`:** a line per attempt however it ended, under the point's lock: `n`, times, identity, card hashes, `verdict`, `cause` (failed, stalled, timeout, count, missing, stopped, prelim), tool `blamed`, message, and per tool its exit, seconds, stall details, warnings, and any prepare cache hit.
- **`records/…/<R>/points.json`:** every point's values, page, products, folders, identity, seed, whether complete, and `state` (complete, stale, running, failed, stopped, incomplete, to run). `constants` are what every point shares: events, threads, parallelism, seed rule, chain, stages, fixed quantities, each tool's folder, version, packages and analyses, base-card hashes, data, revisions, host, stack, image. Post tools, the plot stage and `runner.results` read it, so none must know the layout.
- **`records/…/<R>/tag`:** the folder's tag and labels, the source of truth. It is TOML: `format = 1` and a `[labels]` table, where `tag` is one label and the others are `key = "value"` (`shower = "new"`). A key is a lower-case letter then lower-case letters, digits and `_` (30 at most), never `run`, `events` or `configuration`; a value starts with a letter or digit and holds letters, digits and `. _ + -` (40 at most). A tag of `""` is a cleared tag, which its configuration's `tag` key does not give again. The older one-line file (the tag) and the older empty file (a cleared tag) read as before, and the next write makes them TOML. `record.read_labels`, `run_tag`, `run_labels`, `write_labels` and `write_run_tag` are the readers and writers; `cli.give_tag` writes the tag from `--tag`, the file or the configuration, and leaves the other labels; `heimdall tag` sets or removes any (`plotdoc.write_tag` mirrors them into the plot document's `[source]`). Nothing reads a tag or label into an identity.
- **`identity.json`** beside `.complete`: [identity](identity.md). Its `format` key is outside the hashed parts.
- **A library point** has `library = "<key16>"` in `points.json`, its `identity` is the key (the text of `.complete`), and its files live in the library entry ([identity](identity.md#the-points-library)).

**Format.** `points.json`, `provenance.json` and `identity.json` have `"format": 1` first at top level, and `plot.toml` has `format = 1` in `[source]` (`record.FORMAT`, one number for the record files together). A file without the key is format 0, today's before the key, and reads as it always did. A file of a newer format is refused by the readers (`record.check_format`: update Heimdall): `results.load`, `plot`, `plotdoc.load`, the events reader, `record.why`, `diffcmd`, `reproduce`, `migrate --plot-docs` and `--snapshot`; `heimdall show` prints what a record claims, a newer one too. `identity.json`'s identity is the hash of the file without `format`, so `--why` ignores it. `heimdall records upgrade [--dry-run] [A[/E[/R]]]` gives each record file below format 1 the key, a copy beside it first (`<name>.bak`, then `.bak2`); it refuses while a job of the work dir goes, and leaves the layout moves to `heimdall migrate --layout`.
- **A snapshot** (`record.write_snapshot`): the errand file and what it imports, in `records/…/<R>/config/`, so a record is itself a config.
